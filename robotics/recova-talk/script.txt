Slide 01 / 09 · Combined talk slide 10 · 49 words
Recova

In ASENA, we haven’t yet used those recorded runs to train the policy.
In Recova, we explore that next step: using CAP to collect data and improve a learned manipulation policy.
We wanted to see whether this data could be as useful as—or even better than—human demonstrations.

Slide 02 / 09 · Combined talk slide 11 · 110 words
Recovery keeps collection moving

Our end goal is a reliable learned manipulation policy, like a VLA. We use code as policy to make the whole collection, training, and deployment loop as autonomous as possible.
First, we build a digital twin of the real workstation. A coding agent explores how to perform the task—and how to recover when something goes wrong. Successful trajectories then train two policies: a task policy and a recovery policy.
We deploy those policies on real robots, where an agent monitors progress, triggers recovery, and asks for human help when needed. That experience feeds into the next training round. We improve the policies, deploy them again, and repeat the loop.

Slide 03 / 09 · Combined talk slide 12 · 96 words
Develop corrections in a digital twin

Recovery is what allows the robot to keep going and keep collecting data. Most demonstrations show successful execution, so policies get little experience recovering from mistakes. Recovery demonstrations and DAgger help, but that data is hard to collect.

We use code as policy to explore failures in the digital twin and generate recovery data. We then learn an explicit recovery policy alongside the task policy. When the task gets stuck, recovery can restore the scene or finish the remaining action.

We collect data for both policies and improve them together, each using its own training data.

Slide 04 / 09 · Combined talk slide 13 · 127 words
Learned policies act; a monitor coordinates

On the physical robot, execution is different from the code exploration we just saw in simulation.

A learned task policy generates the motor actions. The VLM monitor observes execution and decides whether the task can continue.

When a recoverable failure occurs, it invokes a learned recovery policy with an instruction. If assistance is needed, the system can fall back to an operator. For a new failure, a human can demonstrate a correction; after training, that instruction is added to the recovery skills available to the monitor.

After the correction, the monitor checks the state before restarting the task. We save task experience and recovery experience into their respective datasets. These can improve the corresponding policies in later rounds. Within one collection round, the policy weights are fixed.

Slide 05 / 09 · Combined talk slide 14 · 70 words
One operator. Four workstations.

On real robots, combining the agent with our learned task and recovery policies gives us a largely autonomous DAgger loop.
Here, one operator supports four workstations. The robots run their policies, recover when possible, and ask for help when needed.
This means we can scale up robot data collection without increasing the number of operators at the same rate. That matters because scaling human supervision is often the harder part.

Slide 06 / 09 · Combined talk slide 15 · 49 words
Less intervention over collection rounds

Like ASENA, we improve over repeated rounds. But here, we use the collected data to update the VLA itself.

As we collect more experience and retrain, the policy gets better. And what’s especially exciting is that human takeover drops to zero in the final collection round of this experiment.
