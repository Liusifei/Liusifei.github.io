# X, B, G1, G2, G3: [batch, channels, height, width]
def gspn_forward(X, B, G1, G2, G3):
    H_minus1 = torch.zeros_like(X[..., 0])
    columns = []
    for w in range(X.shape[-1]):
        top = F.pad(H_minus1[..., :-1], (1, 0))
        bottom = F.pad(H_minus1[..., 1:], (0, 1))
        H_w = (B[..., w] * X[..., w]
               + G1[..., w] * top
               + G2[..., w] * H_minus1
               + G3[..., w] * bottom)
        columns.append(H_w)
        H_minus1 = H_w
    return torch.stack(columns, dim=-1)
Only columns are sequential.

Each tensor operation covers batch, channels and all rows. H_minus1 is a whole previous column. Zero padding supplies missing neighbors.

The first column starts from zero, so its output is simply B · X. This is a teaching rewrite of the full-width recurrence. The implementation uses a custom CUDA kernel ↓.

Gate normalization

Three gates. Row sum = 1.

GSPN paper · Figures 2–3 ↗

Apply sigmoid, then divide by the sum of valid neighboring gates. Each row of the propagation matrix sums to one; products of these transitions preserve that property.

The row-sum guarantee applies to propagation transitions and their products. The complete input-to-output affinity also includes separate input and output gates.

This compares dependency structure, not measured implementations of Mamba or attention. O(√P) describes ideal scan depth with sufficient parallel resources. Total arithmetic and data movement remain linear in P for fixed channels and directions.

Why the distinction matters

A GPU also pays for memory traffic, launches and scheduling. Shorter dependencies create an opportunity; the implementation determines how much of it becomes speed.

What about local chunks, prefix scans and full-block cost?

Independent chunks of length L reduce scan depth to L, but cut context at chunk boundaries. They do not reduce total pixel updates below linear work. Projection and channel-mixing layers add their own costs, commonly O(P C²).

Affine recurrences can be composed associatively. However, multiplying the three-diagonal spatial transitions widens their support; a generic matrix prefix scan loses the cheap three-neighbor representation. The issue is efficient representation, not a mathematical impossibility of parallel composition.

For rectangular maps, the four-direction dependency depth is O(max(H,W)). On fixed hardware, runtime is also limited by available compute, bandwidth and residency; it is not guaranteed to follow the ideal depth curve.

The recurrence performs few arithmetic operations per value moved; coalescing improves useful memory throughput. Meanwhile, finite block residency makes excess work queue in waves—channel compression reduces that queued work.

Kernel implementation scope and occupancy

The original public CUDA source launches 512-thread blocks and one kernel per scan step. GSPN-2’s paper describes fusion, memory coalescing, selective on-chip caching and spatial/channel thread layout. Its public code link still points to the original repository, so the optimized kernel above is an architectural diagram, not a source-code excerpt.

Fusion must retain synchronization between dependent columns. Some large configurations still require multiple launches. The paper describes independent directional passes in separate nonblocking streams; this is not a claim that all four directions are one giant kernel.

The optimized operator’s reported profiles reach roughly 91–93% of peak global-memory throughput in the listed configurations; this is not a whole-model bottleneck claim. Shared memory is not automatically faster than hardware caching. Registers, shared memory and threads limit block residency, so neither a fixed “blocks per GPU” number nor unlimited channel parallelism explains actual throughput.

Scope of the foundation-model claim

The follow-up is a distinct work, with compact latent propagation and cross-operator distillation. Its current hybrid encoder retains a small number of ordinary attention blocks. The propagation core has linear spatial work at fixed channels; that does not make the entire hybrid encoder asymptotically linear.

Operator, block and full-model speedups measure different things. Projections, normalization, feed-forward layers and retained attention all contribute to the end-to-end result.
